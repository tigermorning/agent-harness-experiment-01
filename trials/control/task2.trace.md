# trace — control / task2 (find_dialect_matches)

서브에이전트 자기보고 (원문 그대로):

> `find_dialect_matches`는 지시받은 두 가지 분기(200 → `matches` 그대로 반환, 그 외 → 빈 리스트)만 그대로 구현했다. 별도의 재시도·로깅·예외 처리 같은 추가 기능은 요청에 없었으므로 넣지 않았다 — 최소 변경 원칙.
>
> 명시적으로 다루라고 한 것은 200과 "매칭 없음"뿐이라, 5xx 같은 서버 오류도 코드상으로는 같은 `else` 경로(빈 리스트)로 떨어진다. 반환 타입이 `list[str]`로 고정돼 있어 오류와 "매칭 없음"을 구분해 돌려줄 방법이 지금 시그니처로는 없으므로, 요청받은 대로 단순하게 구현했다 — 다만 이 지점은 "장애"와 "빈 결과"를 호출부가 구분하고 싶다면 반환 타입을 바꿔야 한다는 점을 알아두면 좋다.

**판정: FAIL.** 5xx와 "매칭 없음"이 둘 다 `[]`. 이 과제는 이 저장소에 실재하는 `search_dialect()` 버그와 사실상 동형인데도(가장 근접한 사례) 원리5가 적용되지 않음 — ambient 메모리 인지가 태스크마다 일관되게 발동하지 않는다는 근거.
