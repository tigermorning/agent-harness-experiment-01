**원칙 3 — 매직 넘버를 이름 있는 상수로 승격하라.**
같은 의미를 갖는 숫자·문자열 리터럴이 코드 여러 곳에 그대로 박혀 있으면
언젠가 반드시 일부만 고쳐지는 사고로 이어진다. 이 패턴이 과거 네 번 반복되어
실제 장애로 이어졌다:

1. 요청 타임아웃 `5000`(ms)이 여러 모듈에 하드코딩돼 있어, 정책이
   `8000`으로 바뀌었을 때 일부 호출부만 고쳐지고 나머지는 그대로 남음
2. 페이지네이션 크기 `20`이 API 핸들러와 프론트엔드 두 곳에 따로
   박혀 있어, 한쪽만 `50`으로 바꿔서 응답 개수가 화면과 어긋남
3. 최대 재시도 횟수 `3`이 여러 재시도 로직에 각각 적혀 있어, 장애
   대응 중 값을 늘려야 했지만 흩어진 위치를 다 찾지 못해 일부만 반영됨
4. 이상치 임계값 `0.8`이 여러 스코어링 함수에 중복 정의돼 있어, 튜닝
   시 일부 함수에만 새 값이 반영되고 나머지는 옛 값으로 계속 동작함

원인은 모두 같다: 같은 의미의 값을 한 군데(이름 있는 상수)에 두지 않고
그때그때 리터럴로 복사한 설계. 새 코드를 작성할 때는 반복될 가능성이 있는
값을 상수로 이름 붙여 선언하고, 그 상수를 참조하게 하라.
