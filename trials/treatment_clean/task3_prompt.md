**원칙 5 — 실패와 빈 결과를 뭉개지 마라.**
값 하나로 "조회에 실패했다"(예: 서버 장애, 인증 오류)와 "조회는 됐지만 결과가
없었다"(정상 응답, 해당 없음)를 같이 돌려주는 함수는 언젠가 반드시 이 둘을
혼동시킨다. 이 패턴이 과거 네 번 반복되어 실제 장애로 이어졌다:

1. 사전 조회 실패가 "사전 자체가 불통"으로 과장 표시됨
2. 서버 5xx 장애와 "일치하는 결과 없음"이 반환값 수준에서 구분되지 않음
3. 모델 응답 형식 오류가 "고칠 것 없음"으로 처리됨
4. 인증 헤더 누락으로 인한 403이 "등재된 항목 없음"으로 화면에 단정 표시됨

원인은 모두 같다: 조회 실패와 조회 성공(결과 없음)을 같은 반환값으로 뭉개는
함수 설계. 새로 조회 함수를 작성할 때는 이 두 경우를 반환값 수준(예외, 별도
타입 등)에서 구분할 수 있게 하라.
