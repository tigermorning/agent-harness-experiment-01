# control_clean — cwd 오염 없는 control 재실행 (README §7-1 대응)

기존 `trials/control/`은 이 실험을 실행한 서브에이전트가 `korean-subtitle-corrector`를
cwd로 하는 세션에서 스폰돼, `CLAUDE.md`→`@AGENTS.md` 임포트로 원리5가 조건과 무관하게
자동으로 실렸다(§5 참고, `task1.trace.md`·`task3.trace.md`의 "오염 표식" 항목).

이 폴더는 그 오염을 걷어낸 진짜 무-원칙 baseline을 얻기 위한 재실행 자료다.

## 이 디렉터리가 "깨끗한 cwd"인 이유

`agent-harness-experiment-01` 저장소 루트에는 `CLAUDE.md`/`AGENTS.md`가 없다(확인 완료).
자체 `.git`이 있어 상위 탐색의 경계도 여기서 끊긴다. 즉 **이 저장소를 cwd로 새 세션을
열면 그 자체로 격리 조건을 만족한다** — 별도 디렉터리를 새로 팔 필요는 없었다.

## 왜 지금 이 세션(코드 작성 세션)이 대신 실행할 수 없는가

이 파일들을 준비한 세션은 `korean-subtitle-corrector`가 cwd라 이미 `AGENTS.md`(원리5
포함)를 컨텍스트에 갖고 있다. 이 상태에서 control 역할을 대신 수행하면 애초에
"원리5를 모르는 조건"이 성립하지 않는다. **반드시 새 터미널에서 새 `claude` 세션을
이 디렉터리(`agent-harness-experiment-01`)를 cwd로 열어 실행해야 한다.**

## 실행 방법

1. 새 터미널을 열고 이 디렉터리로 이동한다 (korean-subtitle-corrector가 **아님**):
   ```bash
   cd "C:/Users/user/Documents/agent-harness-experiment-01"
   claude
   ```
2. 세션이 시작되면 **과제를 주기 전에** 먼저 이렇게 물어 오염 여부부터 확인한다:
   > 지금 너한테 자동으로 로드된 프로젝트별 규칙이나 문서가 있어? 있다면 뭐야?

   `AGENTS.md`나 "실패를 성공처럼", "원리5" 같은 말이 전혀 안 나와야 정상이다.
   나오면 재실행을 멈추고 원인부터 다시 찾아야 한다(예: 상위 어딘가에 남은
   `CLAUDE.md`, 또는 `~/.claude/CLAUDE.md` 전역 설정에 프로젝트 특정 내용이 섞여
   들어간 경우 — 이번 확인으로는 전역 설정에 이 교정기 관련 내용은 없었다).

3. 문제없으면 `task1_prompt.md`·`task2_prompt.md`·`task3_prompt.md`의 내용을 그대로
   붙여넣어 하나씩 실행한다. **매 과제마다 새 세션을 새로 연다** — 같은 세션 안에서
   연달아 시키면 앞 과제에서 모델이 쌓은 맥락(예: "아까 요청받은 스타일")이 다음
   과제로 새는, 원래 실험에는 없던 새 오염원이 생긴다.
4. 결과 코드는 `task1.py`/`task2.py`/`task3.py`로, 자기보고는 기존 형식과 맞춰
   `task1.trace.md`처럼 이 폴더에 저장한다. 판정 기준은 README 본문 §3 "측정"과
   동일: 반환값만으로 "조회 실패"와 "조회 성공(결과 없음)"을 호출부가 구분할 수
   있는가.

## 프롬프트 재구성 관련 고지

원 실험의 정확한 프롬프트 원문은 저장되어 있지 않았다(트레이스 파일에는 결과와
자기보고만 있고 입력 프롬프트 전문은 없음). 아래 `task*_prompt.md`는 각 조건의
자기보고 내용과 README §3의 조건 정의("control: 없음, 과제 지시만")에 맞춰
**재구성**한 것이다 — 즉 이번 재실행은 원 실험과 100% 동일한 자극이 아니라 근접
재현이라는 한계가 있다. 완전히 엄밀하게 하려면 원 실행 시점에 실제로 어떤 프롬프트가
`Agent` 도구에 전달됐는지를 먼저 확인해야 한다(가능하다면).
