# trace — control_clean / task2, 2차 오염 시도 (폐기)

**이 시행은 독립 표본으로 쓰지 않는다.**

## 무엇이 오염됐는가

오염 확인 질문에 답하는 과정에서 이 세션이 자발적으로 `README.md`를 열어
**앞부분을 직접 읽었다**고 스스로 보고했다("위에서 앞부분만 직접 읽었습니다").
이 저장소의 `README.md`는 실험 설계 문서 그 자체다 — 원리5 설명, `AGENTS.md`
원문 인용("값 하나로 '못 물어봤다'(조회 실패)와 '물어봤더니 없더라'(정상 응답,
미등재)를 같이 돌려주는 함수는 언젠가 반드시 둘을 뭉갠다"), 4건의 실제 사고
(§62·`search_dialect()`·§78·§79), 가설, fixture별 트랩 설명까지 전부 담고
있다.

그 결과 이 세션은 사용자에게 "이번 실험이 korean-subtitle-corrector의 원리5를
출발점으로 삼고 있다"고 스스로 말할 정도로 실험의 전체 그림을 이미 파악한
상태였다. 이 상태에서 `task2_prompt.md`를 붙여넣어 받은 결과가 이 파일이다.

**증거**: 산출 코드의 독스트링이 README/AGENTS.md 원문의 "못 물어봤다"/
"물어봤더니 없더라"라는 특징적인 대구 표현을 거의 그대로 재사용했다 — 지금까지
다른 모든 clean run이 각자 다른 말로 같은 개념을 설명했던 것과 달리, 이번만
원문과 표현이 일치한다. 이것이 이 산출물을 오염으로 판정한 핵심 근거다.

## 참고용 코드 (오염된 시행이지만 남겨 둠)

`task2_contaminated_attempt2_readme_leak.py` — `DialectLookupError`로 실패/성공
분리 자체는 다른 clean run들과 동일한 모양(PASS로 보임)이지만, 원리5를 이미
알고 있는 상태에서 나온 결과라 표본에 포함하지 않는다.

## 이것이 드러낸, 지금까지 놓쳤던 오염 경로

앞선 오염 두 가지(① `CLAUDE.md`→`AGENTS.md` 자동 임포트, ② 세션 신선도와
무관하게 작업 폴더에 남은 이전 시행 결과를 자발적으로 탐색)에 이어 **세 번째
독립 경로**다: 실험 저장소 자신의 `README.md`(설계 문서)를 세션이 스스로 열어
읽는 것. 이전까지의 "다른 파일을 찾아보지 마라" 지시는 **fixture 과제
프롬프트에만** 들어 있었고, **오염 확인 질문 단계**에는 그런 제약이 없었다 —
"지금 자동 로드된 규칙이 있어?"라는 질문 자체가 에이전트로 하여금 저장소를
훑어보게 만들었고, 그 훑어보기가 `README.md`까지 이어졌다.

## 조치

지시문을 더 추가하는 대신 **물리적으로 제거**했다 — `fixtures/`와 `trials/`
전체를 저장소 밖(`Documents/_experiment01_backup_during_trials/`)으로 옮겨,
남은 시행 동안 `agent-harness-experiment-01/`에는 `.git`·`.omc`·
`.gitignore`만 남도록 비웠다. 프롬프트는 이제 대화창에서 직접 복사하거나,
파일 경로 대신 내용 자체를 전달한다. 지시문(“읽지 마라”)에 기대는 대신
애초에 읽을 것이 없게 만드는 쪽이 지금까지의 반복된 경험상 유일하게 신뢰할 수
있는 방어임을 재확인했다.
